# Client figure production and review

Use the existing Results figure_plan, figure_render and figure_audit routes for quantitative figures; use figure_prompt for schematics. The current account model uses available local tools. Neither route uploads image/data content to text context or launches a cloud drawing model. Fetch the applicable start and check guidance with the public contract and use current rules on every request.

For rendering, identify authorized inputs, columns/ranges, units, comparisons and the supported visual claim. Preserve project utilities and user tool choices. Record necessary transformations. Do not run simulations, fitting or supplied executable code as part of an ordinary plotting request. Missing data or tools remain specific gaps; do not install dependencies automatically.

Render with available tools and save new outputs. Normally export PDF for a manuscript and PNG for viewing. Export SVG when requested and supported, then inspect the actual file; vector appearance does not prove editability. Multi-panel outputs need consistent encodings and scales. Follow the retrieved panel/export rules. The fixed cloud CSV executor remains line/grouped-bar only.

Open every final figure at intended size. Separately review data correspondence, visual readability and file/export integrity. Inspect axes, units, legends, overlap, clipping, baselines and panel correspondence. A script or successful tool response is not visual review. Revise and reopen affected outputs after repairs. A prompt-only schematic request stops at a usable prompt; a requested actual image remains incomplete when no suitable tool is available.

For a local evidence check run python3 <plugin-scripts>/figure_review.py --input <record.json> (py -3 on Windows). The record contains project_root, 1-24 inputs ({path, sha256}, optional columns/ranges/units notes), optional script ({path, sha256}), nonempty rules_versions, unresolved (an empty list only when resolved), and 1-24 outputs. Each output has path, sha256 and checks with data, visual, export entries. Each check entry has status=pass, nonempty evidence explaining the actual check, and reviewed_sha256 matching the final output. Compute SHA-256 from the actual files using local tools. Keep these records local; do not upload project paths to guidance.

The helper only checks bounded ordinary files, PNG/PDF headers, passive SVG structure, hashes and record correspondence. It does not decode images, validate numerical mappings, judge semantics, or establish scientific correctness. Missing/stale checks produce pending. Its evidence_consistent status confirms correspondence only. SVG external assets and active content are unsupported. Never use this helper to label a bitmap as an editable vector. Do not pass binary figures to the text artifact checker.

Caption and Results edits use their separate text operations only when requested. Check the final figure against their units, notation and numerical statements; scan/check the actual final text through the content workflow. Keep each stage's actual rules version. Return requested figure files and relevant editable source, actual review scope and unresolved issues. Preserve previous outputs.
